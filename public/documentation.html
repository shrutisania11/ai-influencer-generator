1. Platform Overview & Design Philosophy

The AI Influencer Generator & Auto Post Scheduler is a state-of-the-art software-as-a-service (SaaS) application engineered to empower content creators, digital marketers, and agencies to construct custom synthetic personas (AI Influencers) and automate their presence across key global social networks.

Unlike traditional post scheduling queues, this platform integrates generative media directly into the scheduler. Content creators do not simply schedule text or pre-made pictures; they construct a multi-dimensional digital model that is represented in the database as a visual identity. The system maintains visual consistency across posts by compiling visual character parameters, generating appropriate custom campaign graphics, drafting optimized social media captions, and queuing them to real accounts.

1.1 Core Architecture Principles

  • Consistent Identity Rendering: Generates portraits and full-body model variations using precise generative descriptions, bypassing identity drifting between individual renders.
  • Strict Resource Tokenomics: Incorporates credit-based quotas (50 credits for character design, 20 credits for post generation) verifying balances prior to billing external APIs.
  • Robust Schema Agnosticism: Implements deep-level try-catch models and sandboxed fallbacks so that database updates or missing API integrations never break the dashboard experience.
  • Intuitive Client Dashboards: Implements sleek, responsive visual indicators, hover states, drag-and-drop calendar queues, and inline subscription simulations.

3. Comprehensive Database Schema (SQL)

The data system is managed using Supabase (PostgreSQL). The structural links are governed by CASCADE constraints ensuring data integrity. If a user deletes their account, all related custom models, campaign posts, and social tokens are cleaned up securely.

3.1 Complete SQL Table Setup

Execute the following SQL instructions inside your Supabase SQL Editor to establish the relational schemas: 

-- 1. USERS TABLE
CREATE TABLE public.users (
    id UUID PRIMARY KEY REFERENCES auth.users ON DELETE CASCADE,
    email TEXT,
    full_name TEXT,
    avatar_url TEXT,
    credits INTEGER DEFAULT 300,                  -- Entered on standard free tier registration
    subscription_tier TEXT DEFAULT 'free',        -- 'free', 'standard', 'pro'
    subscription_status TEXT DEFAULT 'inactive',  -- 'active', 'inactive', 'canceled'
    stripe_customer_id TEXT,
    stripe_subscription_id TEXT,
    updated_at TIMESTAMP WITH TIME ZONE
);

-- 2. MODELS TABLE (AI INFLUENCERS)
CREATE TABLE public.models (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    gender TEXT,
    body_type TEXT,
    skin_tone TEXT,
    age_range TEXT,
    hair_style TEXT,
    hair_color TEXT,
    eye_color TEXT,
    vibe TEXT,
    prompt TEXT,
    portrait_url TEXT,     -- Signed secure storage link
    full_body_url TEXT,    -- Signed secure storage link
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- 3. POSTS TABLE (GENERATED MEDIA CAMPAIGNS)
CREATE TABLE public.posts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
    model_id UUID REFERENCES public.models(id) ON DELETE CASCADE,
    prompt TEXT NOT NULL,         -- JSON payload containing schedules, subtitles, and publish states
    image_url TEXT,               -- Output CDN asset link
    aspect_ratio TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- 4. SOCIAL ACCOUNTS TABLE
CREATE TABLE public.social_accounts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
    platform TEXT NOT NULL,       -- 'instagram', 'linkedin', 'tiktok', 'youtube', 'pinterest'
    profile_id TEXT NOT NULL,     -- Sync key generated from Zernio
    account_id TEXT NOT NULL,     -- Unique platform channel identifier
    account_name TEXT,
    avatar_url TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL,
    CONSTRAINT unique_user_platform_account UNIQUE (user_id, platform, account_id)
);

3.2 Architectural Table Relationships

The architecture follows a strict 1-to-many cascading parent structure:

  • Every public.models and public.posts belongs directly to an authenticated public.users primary key.
  • Each post generated belongs to a target public.models (AI Influencer), establishing visual alignment.
  • The unique_user_platform_account constraint prevents users from linking the exact same Instagram or LinkedIn channel multiple times, protecting token synchronization.

4. Backend API Pipelines & Server Actions

The application utilizes Next.js Server Actions to securely process calculations on the server, avoiding exposing sensitive API keys to the client.

4.1 AI Influencer Studio Generator

The generation file app/actions/influencers.ts orchestrates the avatar and full-body rendering pipeline:

  1. Credit Auditing: Validates that the active user profile has at least 50 credits. If not, it returns an early error response.
  2. Generative Synthesis: Formulates highly structured textual prompts based on the UI choices and invokes the @fal-ai/client.
  3. Secure Storage Buffer: Downloads the binary image buffer from Fal.ai CDN and transfers it to the Supabase Storage Bucket under public/models/${userId}/${timestamp}.jpg.
  4. Profile Refills & DB Insertion: Deducts 50 credits, updates the user's table, and writes the character parameters to the models table.

4.2 Zernio Unified Social OAuth Integrator

The social scheduler file app/actions/social.ts interfaces with the Zernio Social API:

  • Profile Provisioning: Uses getOrCreateZernioProfile to map users to independent Zernio nodes, securing profile integrity.
  • Fallback Mock Linker: If a developer is working offline or hasn't configured a ZERNIO_API_KEY, the server actions fallback to a robust Mock Linker Simulator. This returns mock keys and logs active simulator badges, enabling the front-end features to run smoothly in sandboxed sandboxes.
  • Unified Post Publishing: Pushes scheduled assets to Zernio's CDN presigned bucket (/media/presign), downloads the file streams, and executes publishing updates for scheduled times.

4.3 Stripe Subscription Gateway

The payment pipeline in app/actions/stripe.ts features elegant developer shortcuts: 

// Dynamic Stripe Product Checkout Configuration
const session = await stripe.checkout.sessions.create({
  payment_method_types: ['card'],
  line_items: [{
    price_data: {
      currency: 'usd',
      product_data: {
        name: 'Pro Premium Monthly Plan',
        description: '3000 monthly credits & unlimited multi-platform posting',
      },
      unit_amount: 4900, // $49.00 USD
      recurring: { interval: 'month' }
    },
    quantity: 1,
  }],
  mode: 'subscription',
  success_url: `${origin}/dashboard/settings?session_id={CHECKOUT_SESSION_ID}`,
  cancel_url: `${origin}/dashboard/settings`,
});

This inline method removes the overhead of manually pre-creating pricing items in the Stripe Dashboard, making setup fast and fully dynamic.

⚠️ Security Protocol: API Key Exposure
Never commit .env.local to GitHub. If you accidently upload your credentials, IMMEDIATELY navigate to the respective developer console, delete the compromised secret, and request a replacement token.

6.3 Development Webhook Tunneling

Because Stripe utilizes asynchronous server callbacks to tell your database that a subscription payment was successful, you must run a webhook listener in development:

  1. Download and install the **Stripe CLI** on your computer.
  2. Log in to your account: stripe login
  3. Start the event forwarding pipeline: 
    stripe listen --forward-to localhost:3000/api/webhooks/stripe
  4. Copy the returned webhook signing secret (starts with whsec_) and paste it as STRIPE_WEBHOOK_SECRET in your local .env.local file.
